## 4. Phased plan

Each phase = one commit (or a tight series). Run tests + ruff + push CI green at the end of each phase. Same discipline as the companion repo.

### Phase 1 — Classical baseline reproduction (LS + LMMSE + soft demap)

Build the classical receiver chain in Sionna so we have the curve to beat. Output: `reports/bler_classical.csv` + `.svg` for the BLER vs SNR sweep on TDL-C.

Tasks:
- `neural_rx/sionna_link.py` — wraps Sionna's CP-OFDM resource grid + pilot pattern (use Sionna's built-in pilot patterns; no need to hand-roll).
- `neural_rx/classical_rx.py` — LS channel estimation + LMMSE equalization + soft LLR demap.
- `scripts/run_bler_classical.py` — sweep SNR (-5 to +20 dB in 2.5 dB steps), 80–200 realisations per point, output CSV + SVG.
- `tests/test_classical_rx.py` — unit tests: high-SNR BLER goes to zero, low-SNR BLER goes to 1.

Acceptance: BLER curve is monotonically decreasing with SNR, with the characteristic Rayleigh-diversity-1 shape. At ~10 dB SNR you should see BLER around 0.1–0.3 for uncoded QPSK on TDL-C — exact numbers depend on subcarrier count and CP length, but the shape is the calibration signal.

### Phase 2 — Neural receiver architecture

Define the DeepRx-style CNN in `neural_rx/neural_rx.py`. Suggested starting architecture (refine based on Sionna tutorials):

- Input: received OFDM resource grid as a real tensor of shape `(batch, n_ofdm_symbols, n_subcarriers, 2)` (real + imag).
- Embed pilot positions as a one-hot mask channel → input is `(batch, n_ofdm_symbols, n_subcarriers, 3)`.
- 4–6 residual conv blocks, channels 32→64→64→32, kernel 3×3.
- Output: `(batch, n_data_symbols, n_subcarriers, bits_per_symbol)` LLRs.
- Tests: forward pass shape sanity, no NaNs on random input.

Reference Sionna's neural-receiver tutorial (`sionna/examples/Neural_Receiver.ipynb` or the equivalent in your installed version) for the canonical reference implementation.

### Phase 3 — End-to-end training pipeline

`scripts/train_neural_rx.py` does the canonical loop:
- Random TDL-C realisation per minibatch
- Random SNR per minibatch (uniform from training range, e.g. -5 to +20 dB)
- Random bits → QPSK → OFDM → channel → noise → received resource grid
- Forward through neural RX → LLRs
- BCE loss against transmitted bits
- Adam optimizer, ~50k–200k steps depending on convergence

Log to TensorBoard or just to JSON. Save best model by validation BLER (held-out fixed SNR set).

Acceptance: training loss decreases monotonically over a smoothed window; validation BLER at fixed SNR (e.g. 5 dB) drops over training.

### Phase 4 — Head-to-head comparison + evidence pack

`scripts/run_bler_comparison.py`:
- Load the trained neural RX
- For each SNR point in -5 to +20 dB:
  - Run N realisations of TDL-C
  - For *each realisation*, feed the SAME received resource grid to BOTH classical and neural receivers
  - Record BLER for each
- Output `reports/bler_comparison.csv` + `.svg`

This is the headline plot. Aim for: *neural matches LMMSE at high SNR, beats it by 1–3 dB at low SNR.* That's the textbook DeepRx result. If you get *much better* — verify there's no leakage (e.g., neural RX accidentally seeing the bits or the channel). If you get *worse* — investigate (training too short, model too small, learning rate, etc.).

Also produce:
- `reports/training_log.json` — final loss, validation BLER curve over training
- `reports/llr_distribution_comparison.svg` — histograms of LLRs from classical vs neural at a moderate SNR (useful AI-PHY diagnostic)

### Phase 5 — Edge deployment

- `scripts/export_onnx.py` — neural RX → ONNX. Sionna models may need to be unwrapped to the underlying PyTorch `nn.Module` first. If Sionna wraps things in a way that breaks ONNX export, document this honestly and either (a) port the trained weights into a clean PyTorch module for export, or (b) leave the ONNX work as a known limitation.
- `reports/onnx_parity_test.json` — sample inputs, run through Sionna model and ONNX runtime, verify outputs match within float32 tolerance.
- `edge/jetson_benchmark.py` — model based on the template at `wireless-link-intelligence-system/edge/jetson_benchmark_template.py`. Outputs p50/p95/p99 latency on the 5090 directly (and ready for Jetson AGX Thor when the user runs it).

### Phase 6 — Dashboard, README, TECH_BRIEF

Same pattern as the companion repo. Specifically:

- **Dashboard** (`build_dashboard.py` → `reports/dashboard.html`):
  - Headline KPIs: classical BLER at 5 dB, neural BLER at 5 dB, dB gain at low SNR, training time on RTX 5090, ONNX latency on 5090, Jetson status.

## 5. Patterns and conventions (copy from the companion repo)

These are not negotiable; they're what makes the portfolio cohere as production-discipline work.

### Engineering practices
- **Tests for every new module.** ruff + pytest gate on every commit.
- **CI runs on every push** (Linux only is fine here; no Windows matrix needed).
- **Deterministic seeds threaded everywhere.** `torch.manual_seed(...)`, `np.random.default_rng(...)`, Sionna's seed argument.
- **Honest disclosure of weak results.** If the neural RX doesn't beat classical, **say so** in the README and dashboard. Don't quietly cherry-pick the best epoch or hide the result.
- **Byte-identical regeneration** is the bar: two consecutive `make verify` runs should produce identical JSON and CSV outputs. PNG/SVG bytes may differ; their content shouldn't.
- **Provenance over flexibility**: legacy exploration notebooks go to `notebooks/legacy/` stripped of outputs. The Python package is the deliverable.

### Framing language (copy exactly)
- Use "**production-discipline reference for AI-PHY**" — not "Foundational", not "AI-RAN-adjacent", not "demo."
- "**The discipline is the deliverable.**" That's the thesis sentence in the README's "Why this exists" section.
- "Surfaced, not hidden" — when reporting weak results.
- "Honest \[X\]" — when calibrating claims (e.g., "honest weak result", "honest BLER curve at low SNR").
- "Sized estimate" / "planning assumption" — when reporting non-measured numbers.

### Anti-patterns to avoid (from `portfolio_philosophy.md`)
- ❌ Marketing language. ❌ Buzzword inflation (no "6G", no "metaverse", no "world model").
- ❌ Speculative architecture diagrams disconnected from the runtime.
- ❌ Fake enterprise complexity. ❌ Unused frameworks.
- ❌ "AI-RAN-adjacent" — if the underlying work supports the harder claim, use the harder claim.
- ❌ Inflating accuracy without honest sample-size and channel-realisation disclosure.

### Commit message style (from the companion repo)
- Single-line subject, optional blank-line + body.
- Subject under 70 chars when possible.
- Body explains *why* and *what's measured*, not *what* (the diff shows what).
- Optional co-authored-by line at the end if the project requires one.
